# ADR 0007: Reprocess-safe chapter keys and extensible schema for text and audio reflections

- Status: Proposed
- Date: 2026-11-09

## Context

Readers use One Chapter not just to receive a daily chapter, but to pause and reflect on what they read. Today, a reader can save a short text note ("A line to keep") on the web. Over time, the reflection model needs to support:

1. **Durability across book reprocessing and re-reading:** Previously, `reflections` was keyed only by `(plan_id, chapter_position)` with `ON DELETE CASCADE` from `plans` and `books`. If an operator reprocessed a book and chapter boundaries shifted by even one item (for example, when a preface split was adjusted), existing notes silently attached to the wrong chapter. If a plan was reset or recreated, notes were tied to the old plan position rather than the chapter itself.
2. **Multi-channel & Audio Reflections (future feature):** Readers will be able to record or send **audio messages / voice notes** as well as text notes about a chapter—for example, replying with a voice message or text message in `@one_chapter_bot` on Telegram, or recording a voice memo in the web reader—with optional speech-to-text transcription in the future.

While audio reflection recording/playback is **not implemented in the initial deployment**, designing the Django models and S3 key layout correctly from day 1 avoids destructive schema rewrites later.

## Decision

### 1. Stable `chapter_key` on `Chapter`

Every `Chapter` row stores both its sequential `position` (`0..N-1` for the daily reading calendar) and a deterministic **`chapter_key`**:

- `chapter_key` is derived from the normalized chapter title (e.g., `slugify(title)`, disambiguated within the book if two chapters share a title, or `pos-{position}` only when a chapter is completely untitled) plus `content_sha256` of the normalized body.
- When an operator runs `onechapter reprocess <slug>` ([ADR 0005](0005-s3-book-originals.md)), chapters are matched and updated in place by `chapter_key` (falling back to `content_sha256` or `position`), preserving each chapter's primary key (`Chapter.id`) even if its `position` shifts.

### 2. Reprocess-Safe, Media-Ready `Reflection` Model

Model `Reflection` in Django ORM so it is anchored to `(reader, book, chapter)` with immutable snapshots of the chapter's identity at the moment the reflection was created:

| Field | Type | Purpose |
| --- | --- | --- |
| `id` | `UUIDField` / `BigAutoField` (PK) | Stable identifier (UUID used for S3 media keys) |
| `reader` | `ForeignKey(Reader, on_delete=CASCADE)` | Owner of the reflection |
| `book` | `ForeignKey(Book, on_delete=PROTECT)` | Book the reflection belongs to |
| `plan` | `ForeignKey(Plan, null=True, on_delete=SET_NULL)` | Optional link to the reading pass/plan |
| `chapter` | `ForeignKey(Chapter, null=True, on_delete=SET_NULL)` | Direct FK to the `Chapter` row (survives `position` shifts on reprocess) |
| `chapter_key` | `CharField` (indexed) | Deterministic chapter slug/key for automatic re-linking if chapters are rebuilt |
| `chapter_position_snapshot` | `PositiveIntegerField` | Chapter day/index when the note was recorded |
| `chapter_title_snapshot` | `CharField` | Chapter title when the note was recorded (guarantees context is never lost) |
| `kind` | `CharField` (`'text' \| 'audio'`) | `'text'` implemented now; `'audio'` ready for voice reflections |
| `source_channel` | `CharField` (`'web' \| 'telegram' \| 'signal' \| 'whatsapp'`) | Where the reflection was captured |
| `body` | `TextField(blank=True)` | Text note, quote, or caption |
| `audio_s3_key` | `CharField(blank=True, null=True)` | Future S3 object key: `media/reflections/{reader_id}/{uuid}.{ext}` |
| `audio_mime_type` | `CharField(blank=True, null=True)` | e.g., `audio/ogg`, `audio/webm`, `audio/mp4` |
| `audio_duration_sec` | `PositiveIntegerField(null=True)` | Duration in seconds for UI playback |
| `external_media_id` | `CharField(blank=True, null=True)` | Optional channel media reference (e.g., Telegram `file_id`) |
| `transcript_text` | `TextField(blank=True, null=True)` | Reserved for future speech-to-text transcription |
| `created_at` | `DateTimeField(auto_now_add=True)` | Creation timestamp |

### 3. Storage & Delivery for Future Audio Reflections

- When audio reflections are enabled in a future iteration:
  - **From Telegram (`@one_chapter_bot`):** Sending a voice note (`message.voice` / `message.audio`) downloads the `.ogg` (Opus) file from Telegram, uploads it to `s3://<bucket>/media/reflections/{reader_id}/{uuid}.ogg`, and creates a `Reflection(kind='audio', source_channel='telegram', ...)`.
  - **From the Web (`app.onechapter.am`):** Browser recordings upload to `media/reflections/{reader_id}/{uuid}.webm` (or `.m4a`) and play back via short-lived **S3 Presigned GET URLs** generated by Django when rendering the chapter view.

## Consequences

- **Notes never get lost or silently scrambled:** Even if a book is reprocessed and chapter indices shift, `Reflection.chapter` and `Reflection.chapter_key` keep the note attached to the exact essay, and `chapter_title_snapshot` preserves human-readable context in all cases.
- **Re-reading works naturally:** Because reflections belong to `(reader, book, chapter)` rather than solely a transient `plan_id`, a reader who finishes a book and re-reads it later sees their past reflections alongside new ones.
- **Zero-migration path to voice notes and AI transcription:** The schema and S3 prefix layout (`media/reflections/`) already accommodate text and audio reflections across Web, Telegram, Signal, and WhatsApp.

## Alternatives considered

- **Keep `reflections(plan_id, chapter_position, body)` until audio is built.** Would require a data migration later and leaves early readers' notes vulnerable to position shifts whenever book splitter rules are refined.
- **Store audio blobs in PostgreSQL.** Increases database backup size and memory pressure; S3 Standard + Presigned URLs is cheaper and streams directly to the browser.
